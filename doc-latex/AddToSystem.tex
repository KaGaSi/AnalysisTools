\section{AddToSystem} \label{sec:AddToSystem}

\tt{AddToSystem} adds unbonded beads and/or molecules to an existing system,
or builds a new system from scratch. New species can be placed randomly or
subject to distance and axis constraints; they can either replace existing
beads or be appended to the system.

\subsection{Defining what to add}

Species to add are specified in one of two ways. The simpler is a \field file
(\tt{<in.field>}) given as the second positional argument, which is read as-is.

The library-based workflow uses \tt{-lib <dir>} to point to a molecule library
and \tt{-mol} to select which species to include. After \tt{-mol}, each entry
is a name--count pair: the count is either an integer number of molecules or a
percentage of the original system's bead count (e.g.\ \tt{10\%} gives
$\text{round}(0.1 \times N_\text{orig} / n_\text{beads})$ molecules, where
$n_\text{beads}$ is the number of beads per molecule). Multiple name--count
pairs can follow a single \tt{-mol} flag, and the flag can be repeated.
Note that percentage counts are meaningless when building from scratch because
the original bead count is zero; use integer counts in that case.

The \tt{-ntot <n> <type>} option (requires \tt{-lib}) adds fill molecules of
type \tt{<type>} until the total bead count reaches \tt{n}. The fill count is
computed via integer division: $\lfloor (\text{target} - \text{current} -
\text{-mol beads}) / n_\text{fill} \rfloor$, where $n_\text{fill}$ is the
bead count of one fill molecule. When building from scratch, the current count
is taken as zero.

When \tt{-lib} is used with an existing system, \tt{-sys <input>} is also
required; it reads a system-info file that maps the existing molecule types to
library names, keeping bead-type names consistent. An updated system-info file
can be written by supplying a second filename to \tt{-sys}. When building from
scratch, a single \tt{-sys} argument is treated as output-only.

\subsection{Placement constraints}

By default, each new bead---or the reference point of each new molecule (the
geometric centre by default; see \cref{subsec:AddToSystem-orient})---is placed
uniformly at random within the simulation box. Two families of constraint can
narrow this region.

\paragraph{Distance constraints.}
\tt{-ld <d>} and \tt{-hd <d>} require the distance from the nearest reference
bead to be, respectively, strictly greater than \tt{d} or strictly less than
\tt{d}; distances are computed with periodic boundary conditions. Reference
beads are selected by type (\tt{-bt <name(s)>}) or taken as all bonded beads
in the system (\tt{--bonded}, which overrides \tt{-bt}); at least one of
these is required when either distance constraint is active. The two can be
combined to restrict placement to a shell at distance $(ld,\,hd)$ from the
reference beads.

When \tt{-hd} is used, the candidate region is pre-narrowed to the bounding box
of the reference beads expanded by the \tt{-hd} value in every direction, which
speeds up placement when the reference beads occupy only a small part of the box.

\paragraph{Axis constraints.}
\tt{-cx <lo> <hi>} (and \tt{-cy}, \tt{-cz}) restrict the corresponding
coordinate of the reference point to the interval $[lo,\,hi)$. By default the
bounds are fractions of the output box sidelength (values in $[0,1]$);
\tt{--real} switches to absolute coordinates. If \tt{lo > hi}, the values are
swapped silently. For a triclinic box the bounds mean something slightly
different---see \cref{subsec:AddToSystem-triclinic}.

Each option takes up to ten \tt{<lo> <hi>} pairs, and the allowed region for
that axis is their union; the pairs need not be given in order, and overlapping
ones---or ones that merely touch---are merged, with a warning. A range is drawn with a probability proportional to its width,
so the density stays uniform over the whole union. The axes are independent---
\tt{-cx} can take three pairs while \tt{-cy} takes one---and the region is the
product of the per-axis unions. For instance,
\begin{center}
  \tt{-cx 0 0.2 0.8 1.0 -cy 0 0.5}
\end{center}
gives two slabs at opposite ends of the $x$-axis, both cut down to the lower
half of the box in $y$.

Distance and axis constraints can be freely combined. \cref{fig:AddToSystem}
shows examples. \tt{AddToSystem} retries placement until all constraints are
satisfied; if no valid position is found within 10\,000\,000 attempts it exits
with an error. No feasibility check is performed in advance, so an
unsatisfiable combination is only detected after all retries are exhausted.

\subsection{Molecular orientation} \label{subsec:AddToSystem-orient}

New molecules are randomly rotated by default, using a ZYZ Euler-angle scheme
that produces a uniform distribution over all orientations. Two options change
this: \tt{--no-rotate} preserves the orientation from the \field file, and
\tt{-a <$\alpha$> <$\beta$> <$\gamma$>} applies a fixed rotation by $\alpha$,
$\beta$, and $\gamma$ degrees around the $x$-, $y$-, and $z$-axes,
respectively (overrides \tt{--no-rotate}). The angles follow the right-hand
rule, and the rotations are composed as $R = R_z(\gamma)R_y(\beta)R_x(\alpha)$,
i.e.\ the $x$-rotation is applied to the molecule first:
\begin{equation}
  R = \left[
  \begin{array}{ccc}
    \cos\gamma\cos\beta &
      \cos\gamma\sin\beta\sin\alpha - \sin\gamma\cos\alpha &
      \cos\gamma\sin\beta\cos\alpha + \sin\gamma\sin\alpha \\
    \sin\gamma\cos\beta &
      \sin\gamma\sin\beta\sin\alpha + \cos\gamma\cos\alpha &
      \sin\gamma\sin\beta\cos\alpha - \cos\gamma\sin\alpha \\
    -\sin\beta &
      \cos\beta\sin\alpha &
      \cos\beta\cos\alpha \\
  \end{array} \right].
\end{equation}

Placement constraints are applied to the molecule's \emph{reference point},
which is the geometric centre by default; \tt{--head} switches this to the
first bead, and \tt{--tail} to the last bead (\tt{--head} takes priority if
both are given). The molecule is rotated around the reference point, which is
then placed at the constrained position. The remaining beads are positioned
relative to it using the rotated \field coordinates, so they are not
themselves guaranteed to satisfy any constraints.

\subsection{Exchange and append mode}

When adding to an existing system, \tt{AddToSystem} by default
\emph{exchanges} beads: for each new bead placed, one existing bead is removed,
keeping the total bead count approximately constant. The type to remove is the
most numerous bead type unless \tt{-xb <type>} specifies otherwise. No check
is done whether the removed bead belongs to a molecule; removing a bonded bead
will leave an incomplete molecule in the output.

Using \tt{--add} appends new species without removing any existing beads,
increasing the total bead count (this overrides \tt{-xb}). When building from
scratch, append mode is always active regardless of \tt{--add}.

\subsection{Box, offset, and scratch mode}

\tt{-b <x> <y> <z>} sets the output simulation box sidelengths (always in
absolute units, regardless of \tt{--real}). Three further numbers,
\tt{-b <x> <y> <z> <$\alpha$> <$\beta$> <$\gamma$>}, add the cell angles in
degrees and make the output box triclinic; without them the box is orthogonal.
Each angle must lie in $(0,180)$ and the six numbers together must describe a
realisable cell, otherwise \tt{AddToSystem} exits with an error. By default the
new box is centred on the original one. All placement constraints refer to the
output box, not the input one.

\tt{-off <x> <y> <z>} shifts all beads from the input system before the new
species are placed. Without \tt{--real}, the amounts are fractions of the cell
vectors (which for an orthogonal box are simply fractions of the sidelengths);
with \tt{--real} they are in absolute units. Periodic boundary conditions are
not applied after the shift, so beads can move outside the box.

To create a system from scratch, pass \tt{-} in place of the input file; the
box is then taken from the \field file or library, including its angles if the
first line of the \field file lists six numbers. In this mode, \tt{-ld},
\tt{-hd}, \tt{-bt}, \tt{--bonded}, \tt{-xb}, and \tt{-st} have no effect and
a warning is printed if any of them are supplied.

An extra output file in any supported format can be written with \tt{-o
<file>}, which is useful when both a \vtf visualisation file and a \data
LAMMPS file are needed from a single run. Use \tt{-ebt <int>} to reserve
extra bead-type slots in a LAMMPS \data output. The random seed can be fixed
with \tt{-s <int>} for reproducibility.

\subsection{Triclinic boxes} \label{subsec:AddToSystem-triclinic}

Triclinic cells are supported throughout: beads and molecules are placed
uniformly inside the tilted cell, and the \tt{-ld}/\tt{-hd} distance checks use
the minimum-image convention appropriate for it. A triclinic output box comes
either from the input file, from a \field file whose first line carries the
three angles, or from \tt{-b} with six numbers.

The axis constraints need more care. A slab bounded by two planes perpendicular
to a Cartesian axis cannot be periodic in a cell tilted in that plane, so there
is no Cartesian sub-box to place beads in. For a triclinic box, \tt{-cx},
\tt{-cy}, and \tt{-cz} are therefore interpreted as fractions along the first,
second, and third \emph{cell vector}, carving out a smaller cell of the same
shape. The constrained region then shears with the cell, so its periodic images
line up as they should. For an orthogonal box the two readings coincide and
nothing changes.

Because of this, \tt{--real} cannot be combined with \tt{-cx}/\tt{-cy}/\tt{-cz}
when the box is triclinic; \tt{AddToSystem} exits with an error asking you to
use fractions instead. The \tt{-hd} option is unaffected: the region it derives
is a bounding box around existing beads, which is axis-aligned regardless of
the cell shape.

Further examples---including incremental builds, asymmetric bilayer assembly,
cylindrical aggregates, and library-based workflows---are in
\tt{Examples/AddToSystem}.
