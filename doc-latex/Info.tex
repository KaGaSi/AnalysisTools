\section{Info} \label{sec:Info}

\tt{Info} reads an input structure file, prints system composition to standard
output, and can optionally write the (possibly modified) system to a structure
file of any supported format.

By default, the utility prints a summary of bead types, molecule types, counts,
and simulation box dimensions. Using \tt{--verbose} additionally prints per-bead
and per-molecule details. When a secondary structure or coordinate file (\tt{-i}
or \tt{-c} option, respectively) is present as well, \tt{--verbose} also prints
the initial composition of each input before the final merged result.

\subsubsection*{Supplementing system information}

A secondary structure file supplied via the \tt{-i} option fills in bead type
properties (charge, mass, radius) that are missing from the primary file,
matching bead types by name. If both files share molecule types with identical
names and bead type order, the secondary file can also supply bond types,
angles, and related topology data absent from the primary file; note that all
bead type parameters must match exactly for this to work.

The \tt{--chbt} option goes further: instead of only filling in missing values,
it re-maps the bead types inside each molecule to those defined in the secondary
file. Molecules are matched by name and bead count; molecule types with
mismatched bead counts are skipped.

For \vtf structure files, bead type identity is determined by bead name alone by
default. The \tt{--detailed} flag additionally uses charge, mass, and radius to
distinguish bead types, so beads sharing a name but differing in other properties
are assigned distinct types. For example, three \tt{atom} lines with the same
name but two different masses and one with no mass normally produce a single
bead type; with \tt{--detailed} they become three separate types (one with
undefined mass).

\subsubsection*{Coordinates}

Structure file formats that natively embed coordinates (\data, \ltrj, \xyz)
include them automatically; for \vtf files, structure and coordinates may differ
(not all beads in the structure block/file have to be in the coordinate
block/file), so to read coordinates from a \vtf file, the coordinate file (e.g.,
the same \vtf file) must be included via the \tt{-c} option. The \tt{-st} option
selects which timestep of the coordinate file to use (default: the first). When
coordinates are available, the system is pruned to contain only the beads
present in that timestep. If no coordinates are read, the system is not pruned,
and all coordinates in the output structure file (\tt{-o} option) will be 0's.

\subsubsection*{Restructuring the system}

The \tt{--frag} option splits topologically disconnected molecules (molecules
whose bonds do not form a single connected graph) into separate fragment molecule
types named \tt{<orig_name>_1}, \tt{<orig_name>_2}, etc. Single-bead
fragments are demoted to unbonded beads.

The \tt{--mol} option converts all unbonded beads into one-bead molecules, using
the bead type name as the molecule type name. This is useful when the output is
to be processed by utilities that only operate on molecules (e.g.,
\tt{Aggregates}).

\subsubsection*{Output structure file}

When \tt{-o} is specified, \tt{Info} writes the final system to a structure
file; the format is inferred from the file extension. Writing to \tt{itp} or
\tt{pdb} is not supported. Only one timestep of coordinates is written.

For \vtf/\vsf output, \tt{-def} specifies the bead type for the
\tt{atom default} line; the default is the bead type with the greatest number of
unbonded beads.

For LAMMPS \data output, \tt{--mass} collapses bead types that differ only in
charge into a single LAMMPS atom type in the \tt{Mass} section while preserving
per-atom charges in the \tt{Atoms} section. The \tt{-ebt} option appends a given
number of extra dummy atom types (mass 1, absent from the \tt{Atoms} section),
useful for, e.g., SRP ghost particles that require pre-declared atom type slots.

\subsubsection*{Library-based bead renaming}

The \tt{-lib} option points to a library directory from which bead type names are
reassigned and DPD interaction parameters are looked up. The resulting interaction
table is printed to standard output in addition to the system composition. When
the output is a \field file (\tt{-o} option), the interaction block is also
appended to that file.

If molecule types in the input file are unnamed, \tt{-sys} supplies a
\tt{system_info} file to assign names to them before library renaming. Without
\tt{-sys}, unnamed molecule types cause the renaming step to be skipped with a
warning.
